## P2 — техническая надёжность; ограничения безопасности действуют сразу

- [ ] **Изолированные проверки ошибок для изменяемого worker/adapter:** внешний timeout и авария в процессе `running` с сохранением причины, без автоматического повторения неоднозначного внешнего эффекта. SQL/API/Run/Scheduler интеграцию проверять на **одноразовой мигрированной PostgreSQL**, не на постоянном Windows volume. Проверенный рестарт Scheduler повторять не надо без новой гипотезы. [DEVELOPMENT.md](DEVELOPMENT.md).
- [ ] **Scoped auth и подтверждение рискованных операций — обязательный барьер перед расширением доступа:** сейчас API локальный без аутентификации; не открывать его внешним клиентам и не выдавать сторонним AI права записи до реализации READ/ADMIN, проверки операций и прав. Это не блокирует нынешний доверенный ручной эксперимент. [SECURITY.md](SECURITY.md).
- [ ] **Защита долговременных данных, когда они станут важными:** проверить backup/restore и восстановимость выбранного хранилища. CI/CD по потребности; начальный `.github/workflows/ci.yml` — source candidate текущего onboarding PR, не установленный runtime gate до owner merge и exact-head CI; GitHub workflow публиковать только через разрешённый Gateway и необходимое одобрение, не ради формальной автоматизации.
