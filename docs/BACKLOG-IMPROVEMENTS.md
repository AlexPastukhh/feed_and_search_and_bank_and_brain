## Сейчас — функциональный результат по поиску заработка

- [ ] **Первый практический Action-инструкция:** зафиксировать параметры и стратегию поиска оплачиваемых задач (.NET/React и любая разработка; 2D/3D; работа, которую реально освоить и выполнить качественно через AI/агентный workflow). Выполнить инструкцию внешним AI **вручную**, получить реальные объявления/сигналы и проверяемые ссылки, оценить применимость к навыкам и рискам. Без AI-worker и нового поискового движка. [UC-ACT-001](use-cases/actions.md#uc-act-001), [UC-ACT-004](use-cases/information.md#uc-act-004).
  - [x] **Инструкция V1 зарегистрирована (2026-11-10):** Action ID `3`, версия `1`; `POST /actions` вернул `201`, `GET /actions/3` подтвердил запись. Точная YAML-копия — [`examples/actions/earning_opportunities_v1.yaml`](../examples/actions/earning_opportunities_v1.yaml). Только инструкция; автоматический AI-executor и `ActionRun` для этого поиска отсутствуют.
  - [x] **Первый ручной пробный поиск (2026-11-10):** предварительная подборка из поисковой выдачи Upwork (7 разовых/проектных и 2 долгосрочных примера), сформулированы гипотезы услуг; сами карточки и возможность отклика повторно не подтверждены. Отчёт носит разведочный, не верифицированный характер — [`первый поиск`](research/earning-opportunities-2026-11-10.md).
  - [ ] **Следующее исследование после уточнения инструкции:** изучить направления и признаки спроса на разных площадках, включая 2D/3D, автоматизацию и портфолио; проверять первоисточники для ключевых выводов и выявлять подходящие Sources. Конкретные заказы допустимы как свидетельства, но не являются обязательным количеством или статистическим набором.
  - [ ] **Полезный сохраняемый результат:** сохранить исследовательские выводы, подтверждения и кандидаты источников для повторного чтения во внешнем инструменте, когда будет подтверждён его контракт (см. UC-ACT-005); накопление истории отдельных объявлений относится к мониторингу.

- [ ] **Готовое приложение фида:** выбрать существующий сервис, подтвердить публикацию персональных находок, повторное чтение/поиск пользователем и внешним AI, дедупликацию/обновление по фактическому контракту. OPML — только список RSS-подписок, не доказательство настроенного фида. Не строить UI или обязательное хранилище результатов в ядре. [UC-ACT-005](use-cases/information.md#uc-act-005).

**Ближайший проверяемый результат после внедрения метки:** исследовательский Action #3 v2 позволяет обоснованно пересмотреть фокус, выделить направления, пробелы и источники для будущего мониторинга. Примеры заказов используются для доказательств по необходимости; не требовать фиксированное число объявлений. Успех регистрации или поисковый сниппет не доказывает полезность исследования.

## После первой проверки — только обнаруженные потребности

- [ ] Под конкретный полезный Action подключить/разработать устойчивую операцию поиска и отбора, если её нельзя удобно выполнять существующими Tools; Source и критерии задаёт Action. Проверить разную выдачу на разных параметрах без изменения кода Tool. [UC-ACT-003](use-cases/information.md#uc-act-003).
- [ ] На следующем полезном сценарии проверить программное end-to-end выполнение (без AI): реальная операция Tool, история и фактический результат. Подключать новый Tool **не ради количества интеграций**. [UC-ACT-002](use-cases/actions.md#uc-act-002).
- [ ] Для постоянного мониторинга использовать доступные расписания; проверять новые/изменённые находки и отсутствие нежелательных дублей. Не заставлять все Sources проходить через Feedbrain.
- [ ] Если потребуются сводки за месяц/год или сопоставление исследований, выбрать готовую таблицу/сервис графиков; проверить показатель по первичным данным и повторное обновление того же внешнего объекта. [UC-ACT-006](use-cases/information.md#uc-act-006).
- [ ] По конкретной потребности добавить другие темы: обновления технологий/AI-workflows, мировые или интернет-показатели, новые способы решения задач, исследование игрового рынка; новые алгоритмы только при выявленном пробеле. [UC-ACT-003](use-cases/information.md#uc-act-003).
- [ ] При наличии доступа к приложению планирования проверить чтение цели/решений, поиск новых вариантов, критериев и потенциальных ошибок и сохранение **предложений**, без автоматического изменения данных. [UC-ACT-008](use-cases/information.md#uc-act-008).

## Незавершённые проверки и безопасность

- [ ] Проверить **внешний timeout** в настоящем ActionRun/StepRun и сохранение ошибки на изолированном сценарии.
- [ ] Проверить **аварию worker во время уже начатого выполнения**, восстановление зависшего Run и отсутствие автоматического повтора неоднозначного внешнего эффекта. Перезапуск только Scheduler с сохранённым расписанием **уже подтверждён** — см. [PROJECT.md](PROJECT.md).
- [ ] Запустить SQL/API интеграционные тесты, включая проверку trigger, ActionRun и Scheduler, **только на disposable PostgreSQL**, не на постоянном Windows volume. [DEVELOPMENT.md](DEVELOPMENT.md).
- [ ] Перед предоставлением сторонним исполнителям прав на изменения — реализовать scoped auth/READ/ADMIN, безопасную политику операций и подтверждение рискованных изменений. [SECURITY.md](SECURITY.md).
- [ ] CI/CD пока отложен; перед использованием как надёжного архива проверить backup/restore. GitHub workflow, если понадобится, публикуется только через Gateway с нужными правами и одобрением.

## Более поздние или условные возможности

- [ ] При доказанной необходимости интегрировать **автоматического AI-исполнителя**: чтение Action, запуск с доступными Tools, возврат результата, версия и provenance. Ручное выполнение инструкции этому не равно. [UC-ACT-007](use-cases/actions.md#uc-act-007).
- [ ] Для смешанных Actions реализовать проверяемую точку **ожидания действия AI/пользователя** с адресатом, инструкцией, входом, безопасным однократным возобновлением и отдельной историей отказа/тайм-аута. [UC-ACT-007](use-cases/actions.md#uc-act-007).
- [ ] Событийные/календарные триггеры, условия, бюджеты/стоимость, расширенные retry/recovery, вложенные Actions и готовый workflow engine — **только под конкретную задачу**; проверить эффект и политику доступа.
- [ ] Расширять Feedbrain (API-источники, HTML/PDF/CSV/JSON, накопление/индексация/специализированный retrieval) лишь когда нужен постоянный механический сбор/архив и доступные внешние Tools не решают задачу. Не вводить обязательный централизованный поток данных.
- [ ] По мере фактических интеграций проверить bounded history/provenance, реальные инструменты и версии внешних объектов; не вводить универсальный artifact registry заранее.

**Не блокирует ближайшую функцию:** встроенная LLM, автономная multi-agent платформа, собственные движки графов/графиков, массовые коннекторы и production-инфраструктура. История прежних фаз находится в Git; завершённые проверки не копируются в backlog.
