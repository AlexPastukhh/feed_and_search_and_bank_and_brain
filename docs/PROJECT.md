5. **Граница проекта**: Action System — целевая центральная подсистема; Feedbrain — самостоятельный опциональный сервис, через который Actions могут получать заранее накопленные материалы. Внешние приложения/API/MCP — полноценные альтернативные инструменты.

## Current State — что есть прямо сейчас

**Коротко:** Feedbrain уже можно запустить и использовать как RSS-архив с поиском. **Action System, модели Actions и механизм управления их запусками пока не реализованы.** Реальный AI получил доступ к Feedbrain через Fortis Repo; это не готовый Action Executor.

| Компонент | Текущее состояние | Проверка/ограничение |
|---|---|---|
| Runtime | FastAPI, PostgreSQL 16, Alembic, API + worker в Docker Compose | Старт и миграции подтверждены на Windows Docker Desktop |
| Feedbrain Source/Subscription | RSS/Atom, ручная синхронизация и автоматический polling пока worker работает | Проверен реальный RSS Simon Willison |
| Ingestion | Очередь `IngestionRun`, дедупликация, ETag/304, версии `ResourceVersion` | Проверено сохранение 30 публикаций; число относится к тесту |
| HTML content | Trafilatura, извлечение доступного текста публичной статьи | **Только по запросу**, проверено на одной статье |
| Content search | PostgreSQL FTS, `ContentChunk`, поиск по заголовку и фрагментам | Поиск `weight` возвращал реальные `chunk_id` |
| External AI access | HTTP API Feedbrain доступен через Fortis Repo | На проверенной сети `host.docker.internal:8000`; не универсальная гарантия |
| Action Core | **Не реализован** | Нет `Action`/`ActionVersion`/`ActionRun`/`ActionResult` в БД/API |
| Tools/Execution | **Не реализована единая граница Action execution** | Ручной доступ ChatGPT к инструментам ≠ автоматический исполнитель |
| Schedules | RSS polling реализован; Action scheduling **нет** | Сохранение Action не запускает AI по времени |
| Representations | Поиск по chunks есть; универсальный менеджер представлений **не реализован** | Внешние таблицы, графы, Goal Map могут работать напрямую |
| Security | API Feedbrain без аутентификации | Local-only прототип; нет READ/ADMIN и scoped token |
| CI и надёжность | Есть шаблон CI; активного workflow и проверенного backup/restore нет | Интеграционный набор требует одноразовой PostgreSQL БД |

**Данные и точность:** RSS-хранилище сохраняет исходный XML item, не полный сырой HTML; статус `full` означает извлечённый доступный основной текст, не обход paywall. FTS ищет по fragments, поэтому несколько hits одной статьи — ожидаемое поведение; семантического поиска нет. Фоновая массовая веб-экстракция, расширенный импорт PDF/CSV/JSON, generic API connectors и встроенная LLM не реализованы.

**Следующий шаг:** **Phase 1 — первый Action end-to-end**: создать и сохранить Action, выполнить простой YAML Workflow через Broker и Feedbrain API, увидеть историю, затем подтвердить запуск по расписанию. Контракт и детали: [ACTION-CORE.md](ACTION-CORE.md). Feedbrain расширяем только под конкретную задачу.

## Plan — что делать дальше

### Phase 0. Техническая база Feedbrain — готово

- [x] Runtime: база, миграции, API, отдельный worker и Docker Compose.
- [x] Первый реальный сбор RSS и сохранение версий.
- [x] HTML extraction по запросу, chunking и проверенный поиск.
- [x] Проверен HTTP-доступ внешнего AI через Fortis Repo.
- [x] Зафиксированы целевые границы Action System / Feedbrain / внешних инструментов.

**Готовность Phase 0** не означает, что Feedbrain полностью закончен: новые возможности добавляются по необходимости.

### Phase 1. Action Core — **первая рабочая версия end-to-end**

**Подробная спецификация и границы:** [ACTION-CORE.md](ACTION-CORE.md). Центральная задача: доказать полный цикл **создание Action → сохранение → чтение через Fortis Repo → ручное выполнение YAML Workflow через Broker и Feedbrain → история → автоматический запуск по расписанию**. Без LLM в исполнительном контуре.

- [ ] **Минимальный формат:** определить и валидировать YAML (читаемая инструкция, необязательный Workflow, последовательные шаги, capability и параметры; отдельно интервал расписания).
- [ ] **Registry/API:** создать/прочитать Action, сохранить неизменяемые версии, выдать Action внешнему AI через доступный HTTP-инструмент Fortis Repo.
- [ ] **Broker/adapter:** реализовать `information.sync` через существующий Feedbrain API с настройкой логического источника и ожиданием завершения асинхронного `IngestionRun`.
- [ ] **Execution/history:** очередь ActionRun, worker, шаги/результаты, статусы, ошибки, реальные идентификаторы Feedbrain, неизменность истории v1/v2.
- [ ] **Action schedule:** автоматические запуски по простому интервалу и защита от двойного выполнения, повторов/зависших задач; отдельная от RSS polling логика.
- [ ] **Проверка на Windows Docker:** реальный ручной и плановый Run, чтение и запуск из Fortis Repo, негативный сценарий, миграции и тесты в изолированной БД.

**Definition of Done:** реальный Action вызывает Feedbrain через Broker, показывает завершённый Feedbrain IngestionRun, историю и результат, выполняется без запроса к AI по расписанию; изменённая версия не переписывает историю. **Не входит:** AI/локальные модели как workflow-операции, универсальный реестр всех инструментов, сложный DSL, графы и UI.

### Phase 2. Другие инструменты и расширение Workflow

- [ ] Подключить вторую реализацию совместимой capability и проверить замену без переписывания ActionVersion.
- [ ] Добавить передачу результата шага в следующий шаг, если потребуется конкретному Action; проверить смешанные программные операции.
- [ ] Проверить совместимость дополнительных инструментов/API/MCP, корректные ошибки при отсутствии возможностей и ограничения разрешений.
- [ ] По необходимости добавить AI как **один из вызываемых инструментов**; не требовать встроенной LLM для простых Actions.

**Definition of Done:** новая интеграция подтверждена настоящим Action, а не только зарегистрирована в конфигурации.

### Phase 3. Содержательный Action с внешним AI

- [ ] Дать AI прочитать Action, получить доступные инструменты, инициировать запуск или выполнить инструкцию и зарегистрировать результат.
- [ ] Проверить сценарий Goal Map: читать цели/решения, искать новые способы и подготовить предложения (не менять данные автоматически); либо исследование игрового рынка по параметрам.
- [ ] Сравнить результаты разных версий Action и сохранить ссылки на использованные источники и внешние объекты.

**Definition of Done:** AI работает с версионируемым Action и реальными сторонними инструментами, а результат и происхождение данных доступны в истории. Не писать в ядре предметную логику Goal Map/рынка игр.

### Phase 4. Расширенное управление исполнением

- [ ] По необходимости добавить события/триггеры, календарные расписания, условия, бюджеты, учёт затрат и более сложные retry/recovery.
- [ ] Проверить автоматический запуск доступного внешнего AI executor (сначала определить способ постоянного исполнения).
- [ ] Рассмотреть запуск вложенных Actions с ограничением рекурсии и прав доступа.
- [ ] Отдельно выбирать готовый workflow engine, если простой YAML/worker станет недостаточен.

**Definition of Done:** новая автоматизация подтверждена end-to-end, а разрешения, причины неудач и результаты проверяемы.

### Phase 5. Накопительные представления

- [ ] Выбрать одно реальное представление: внешний dataset, таблица, временной ряд, граф, диаграмма или документ.
- [ ] Определить ссылку на представление, параметры обновления (`append/merge/replace/recompute`) и источники данных.
- [ ] Выполнить несколько Actions, обновляющих **один и тот же** объект через предоставленный приложением инструмент, сохранив ссылки в истории.
- [ ] Проверить корректность накопления и возможность использовать результат в следующем Action.

**Definition of Done:** обновление существующего представления подтверждено на реальном внешнем/собственном сервисе; ядро Action System не дублирует его графический/табличный движок.

### Phase 6. Расширение Feedbrain и других инструментов — **только по потребности**

- [ ] Перед каждой новой интеграцией зафиксировать конкретный Action и отсутствующую capability.
- [ ] Сначала проверить, нет ли готового инструмента/API/MCP с нужным контрактом.
- [ ] Если нужен постоянный сбор **без LLM** или собственная история/индекс — развивать Feedbrain: например, API subscriptions, автоматическое HTML extraction, PDF/CSV/JSON, observations, специализированный retrieval.
- [ ] В остальных случаях подключить готовый сервис напрямую; не заставлять весь поток данных проходить через Feedbrain.

**Definition of Done:** каждое расширение обосновано задачей, проверено end-to-end и не создаёт ненужный дубликат доступного инструмента.

### Поперечные задачи и ограничения

- [ ] **Security (до расширения прав доступа):** продумать аутентификацию, read-only/admin и scoped permissions для Feedbrain/Action API; не выдавать сторонним AI неограниченную запись. Детали — в [SECURITY.md](SECURITY.md).
- [ ] **History & provenance:** хранить версии инструкций, использованные инструменты, ссылки на доказательства и результаты; не путать данные источника с инструкциями для AI.
- [ ] **Эксплуатация:** включить CI и протестировать backup/restore до использования как надёжного архива.
- [ ] **Документация:** обновлять Current State, отмечать `[x]` и дописывать History при каждом подтверждённом результате.

**Не блокирует MVP без конкретной потребности:** встроенная LLM, собственный движок графов, автономный multi-agent framework, pgvector, новый frontend и массовое количество коннекторов.
