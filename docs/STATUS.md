# Реальное состояние проекта

> **Актуально на 2026-11-04.** Это единственное место, где поддерживается перечень реализованных и запланированных возможностей. За концепцией и определениями — в [ARCHITECTURE.md](ARCHITECTURE.md); за командами запуска — в [DEVELOPMENT.md](DEVELOPMENT.md).

## Где проходит граница продукта

**Action System** — целевой слой постановки, исполнения, планирования и истории пользовательских Actions с подключаемыми инструментами. **В репозитории пока не реализован.**

**Feedbrain** — реально работающий локальный Python-сервис накопления и поиска информации, предоставляющий HTTP API. Он **не является обязательным компонентом** Action System и не содержит AI-модели.

## Проверенные возможности Feedbrain

| Область | Состояние |
|---|---|
| Docker Compose: PostgreSQL 16, API, worker и one-shot migrations | Реализовано; запуск проверялся в Windows Docker Desktop |
| Health endpoints: `/health/live`, `/health/ready` | Реализовано |
| RSS/Atom Source и Subscription | Реализовано |
| Ручной sync и фоновый polling подписок по интервалу | Реализовано; работает, пока запущен worker |
| IngestionRun: очередь, статусы, попытки, восстановление зависших запусков | Базовая реализация |
| RSS парсинг, ETag/Last-Modified, дедупликация и версии | Реализовано |
| Resource/ResourceVersion, привязка к Subscription | Реализовано |
| Извлечение текста публичного HTML (Trafilatura) | По запросу `POST /resources/{id}/extract`, **не** автоматически на все статьи |
| ContentChunk, PostgreSQL FTS/GIN и поиск по заголовку | Реализовано; проверено на реальных статьях |
| HTTP API чтения публикаций и поиска | Реализовано; подключено к Fortis Repo |
| Доступ из Fortis Repo к локальному API | Проверен через `http://host.docker.internal:8000` на конкретной машине; не универсальная гарантия сети |
| Доступ из Windows | Проверен через `http://127.0.0.1:8000` |

Из ранее проведённого практического теста: 30 RSS-публикаций Simon Willison сохранены, затем из одной статьи извлечён текст и найдены релевантные ContentChunk. Это **результат тестовой среды**, не гарантированное количество записей после развёртывания. Фрагменты выдаются по одному, поэтому одна статья может встречаться в результатах несколько раз; заголовок может совпасть при `rank=0` для самого фрагмента.

**Сохранение исходного RSS XML item не равнозначно сохранению сырого HTML страницы.** Веб-экстрактор сохраняет извлечённый текст и метаданные происхождения; оригинальный HTML как Blob/Artifact не сохраняется. Статус `full` отражает доступный извлечённый текст, а не обход закрытого контента.

## Не реализовано

| Подсистема | Что отсутствует |
|---|---|
| Action System | `Action`, `ActionVersion`, `ActionRun`, `ActionSchedule`, история событий, policies и автоматический запуск AI |
| Tool integration | Реестр capabilities/connections, универсальный MCP-интерфейс и контроль внешних инструментов |
| Representation management | Универсальное управление представлениями, накопительными датасетами, графами, графиками и внешними артефактами |
| Источники Feedbrain | Импорт PDF/CSV/JSON/файлов, generic API-коннекторы, специализированные поисковые адаптеры и общий ручной URL import |
| Content | Фоновое массовое извлечение полного текста HTML, семантический поиск и полнофункциональный мультиязычный ranking |
| Предметная модель | `Entity`, `Observation`, `DatasetProfile`, `Artifact`/BlobStorage, `Evidence` |
| AI | Встроенный LLM gateway, суммаризация и собственный AI Q&A/Research workflow |
| UI | Пользовательский интерфейс источников, Actions и результатов |
| Безопасность | Аутентификация API, права READ/ADMIN, scoped tokens, гарантированная изоляция сетевого доступа |
| Эксплуатация | Проверенная процедура backup/restore, активный GitHub Actions CI |

**Примечание:** RSS `read_enabled`/`research_enabled` — лишь флаги назначения материала, **не роли/права доступа**.

## Ближайшие проверяемые шаги (предложения, не обязательный roadmap)

1. Зафиксировать контракт Action/ActionVersion/ActionRun, scope разрешённых инструментов и ссылок на результаты; попробовать один **ручной** запуск через уже подключённый AI и реальные API/MCP.
2. Ограничить доступ к Feedbrain API, прежде чем давать широкому набору инструментов операции записи; отделить read-only от admin.
3. Добавить minimal Action history/versions; затем подтвердить механизм планирования с реально доступным исполнителем. Расписание Feedbrain RSS и Action Scheduler не смешивать.
4. Проверить одно накопительное представление во внешнем приложении (например, Goal Map/таблицы/график). Не переносить данные и логику сервиса внутрь платформы без нужды.
5. Расширять Feedbrain только для реальных задач — например, нужен регулярный сбор конкретного API, истории наблюдений или избирательная долговременная индексация.

Встроенный AI, визуализация, новые коннекторы и самостоятельный workflow engine **не обязательные зависимости** первых Action-сценариев. Детали эксплуатации и проверки кода — в [DEVELOPMENT.md](DEVELOPMENT.md).

## Ограничения подтверждения

На Windows проверялись запуск Compose, RSS → PostgreSQL, веб-экстракция и поиск; доступ по HTTP проверялся также через Fortis Repo. Это не означает прохождение полного automated end-to-end/нагрузочного/безопасностного тестирования. В среде Fortis нет Docker Engine и установленных зависимостей приложения; там выполнялись синтаксические проверки и чистые unit-тесты. Шаблон CI лежит в `ci/workflow-template.yml` и ещё не активирован в `.github/workflows/`.
