# Исследовательские результаты и решения по предложениям

Это **предметный контракт для Research Action №3**, а не новое обязательное
поле или универсальная система артефактов Action Core. См.
[UC-ACT-001](../use-cases/actions.md#uc-act-001),
[UC-ACT-004](../use-cases/information.md#uc-act-004) и
[UC-ACT-009](../use-cases/review-results.md).

## Что производит Action №3

Каждое исследование объявляет и выдаёт четыре раздела:
`sources` — кандидаты информационных источников;
`research_action_proposals` — идеи новых/изменяемых исследований;
`monitoring_action_proposals` — идеи новых/изменяемых наблюдений;
`overview` — выводы, фокус и следующие решения.

Вспомогательные поля: `metadata` (дата, версия Action, вопрос,
`execution_mode: external_ai_manual`, охват), `evidence` со ссылками
на основания. Значения разделов не равнозначны созданным Sources/Actions.
Пустые списки разрешены с объяснением причин. У элементов — стабильные ID:
`SRC-001`, `RES-001`, `MON-001`, у доказательств — `EV-001`.
Предложение содержит `change: create|update`, `target_action_id`
(для новых — `null`), `suggested_changes`, `reason`, `evidence_ids`,
`status: proposed`. В `overview` — свободная интерпретация с проверяемыми
основаниями, ограничениями и списком следующих решений.

Файлы одного запуска:
- `result.json` — структурированный объект с четырьмя результатами.
- `report.md` — человекочитаемое объяснение со **строго теми же ID**.

Проверяйте согласованность, не придумывайте доказательств. Схема
`result.json` пока специфицирована здесь на уровне конкретного Action;
ядро не навязывает другим Actions этот формат.

## Где сохранять сейчас

В рамках доступных интеграций первый вариант — приватный Git-репозиторий,
адрес в `docs/research/action3/runs/<YYYY-MM-DD>-<run-key>/`.
Индекс: [action3/README.md](action3/README.md).

Это проверяемое хранилище для нечастых исследований, **не** API автоматической
публикации результатов и не замена персональному фиду. Запись — только
через Fortis task worktree → typed Gateway → PR → слияние владельцем →
синхронизация main. До merge адрес в `main` не считается сохранённым.

В Git не помещать клиентские секреты, закрытые файлы и чувствительные
первичные данные. При отсутствии разрешённого пути записи:
`not_saved` с приложенными файлами, не ложная публикация. В будущем
можно использовать другое готовое хранилище по UC-ACT-005, если его
контракт записи/поиска и права действительно подтверждены.

## Обсуждение и последующие действия

По сохранённому `report_id#MON-001` или `report_id#SRC-002`:
прочитать результат и Evidence; проверить возможность Source/Tool, права,
существующий Action и актуальную версию; **после решения пользователя**
создать/версионировать Action через Registry, либо настроить внешний источник
через API его Tool. Предложения **не** исполняются автоматически.
Исторический `result.json` не меняется при согласовании; факт решения,
новый ActionVersion и проверенный эффект фиксируются отдельно.
