# Action System — локальный реестр Use Cases

Этот реестр описывает **повторяемые способы использования Action System**, а не API-справочник и не список будущих функций. Его владелец — репозиторий feed_and_search_and_bank_and_brain. Данные о том, что действительно реализовано и проверено, принадлежат [PROJECT.md](../PROJECT.md); нормативные понятия и границы — [ARCHITECTURE.md](../ARCHITECTURE.md), фактический YAML/API V1 — [ACTION-CORE.md](../ACTION-CORE.md).

## Быстрый вход

| Ситуация | Use Case | Назначение |
| --- | --- | --- |
| Нужно зафиксировать задачу, даже если она пока только инструкция для AI | [UC-ACT-001](actions.md#uc-act-001) | Создать и версионировать Action |
| Задача исполняется обычной программой, без AI | [UC-ACT-002](actions.md#uc-act-002) | Запуск и наблюдение за результатом |
| Нужно исследовать, обнаруживать новое или отслеживать изменения | [UC-ACT-003](information.md#uc-act-003) | Параметры, источники и стратегия |
| Нужно исследовать направления заработка и определить фокус | [UC-ACT-004](information.md#uc-act-004) | Стратегическое исследование, признаки спроса и источники мониторинга |
| Результат нужно видеть в персональном фиде или дать AI его прочитать | [UC-ACT-005](information.md#uc-act-005) | Передача во внешнее приложение |
| Нужны сравнения исследований, показатели и графики за период | [UC-ACT-006](information.md#uc-act-006) | Повторное использование результатов |
| Работа требует промежуточного действия AI или человека | [UC-ACT-007](actions.md#uc-act-007) | Ожидание и возобновление |
| Нужно изучать альтернативы для задач в приложении планирования | [UC-ACT-008](information.md#uc-act-008) | Исследование по контексту цели |
| Нужно обсудить сохранённый результат и применить выбранные предложения | [UC-ACT-009](review-results.md) | Отчёт → ID предложения → решение → проверенное изменение |
| Нужен полный цикл исследовательского отчёта и отдельного решения | [UC-ACT-010](result-lifecycle.md#uc-act-010) | Research run → сохранение → обсуждение → отдельное действие |

| Внешний AI уже выполнил Action; нужно записать факт и прочитать историю | [UC-ACT-012](external-run.md) | External AI → результат → регистрация без автозапуска |

## Семантика и владельцы

**Нормативные определения Action, Tool, Source, исполнения и результатов** — в [ARCHITECTURE.md](../ARCHITECTURE.md); уточнение **операционных режимов исполнения** — в [EXECUTION-MODES.md](../EXECUTION-MODES.md); точные ограничения V1 — в [ACTION-CORE.md](../ACTION-CORE.md). Здесь — только повторяемые пользовательские сценарии и критерии их проверки.

Action с одной инструкцией для внешнего AI допустим **как сохранённое определение**, но сам по себе не создаёт исполняемый Run. Программные Actions могут исполняться без AI; ожидание действия AI/пользователя — отдельная будущая возможность, [UC-ACT-007](actions.md#uc-act-007).

## Как читать статусы

- **Работает частично:** есть проверенные элементы (например, Registry, Broker, Scheduler и Feedbrain), но весь сценарий ещё не принят end-to-end.
- **Целевой сценарий:** описано ожидаемое поведение; нельзя считать его поддерживаемым без отдельной реализации и проверки.
- **Можно вручную:** человек или внешний AI может выполнять инструкцию доступными средствами, но это не тождественно автоматическому выполнению/истории в Action Core.

При неопределённости возможностей внешнего приложения или прав доступа — **STOP / UNKNOWN**, не выдумывать интеграцию. Открытые разработческие задачи хранить в [BACKLOG-IMPROVEMENTS.md](../BACKLOG-IMPROVEMENTS.md), а проверенные факты — в [PROJECT.md](../PROJECT.md), не в реестре.
