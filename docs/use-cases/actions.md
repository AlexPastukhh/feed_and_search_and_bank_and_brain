# Actions: создание, выполнение и внешний участник

Термины и границы определены [архитектурой](../ARCHITECTURE.md). Реальный контракт V1 см. в [ACTION-CORE](../ACTION-CORE.md), степень проверки — в [PROJECT](../PROJECT.md). Ни один из сценариев ниже не объявляет новые API уже реализованными.

## UC-ACT-001

**Когда:** нужна повторяемая задача поиска, мониторинга, исследования или другой работы, но способ её исполнения пока может меняться или быть неизвестным.

**Цель:** сохранить одну понятную человеку и исполнителю версионируемую задачу, которую можно менять без переделки стабильных инструментов.

**Предпосылки:** определены цель, существенные ограничения, ожидаемый полезный результат и доступный способ прочитать Action. Наличие конкретного Tool не обязательно для хранения инструкции.

**Как:**
1. Описать, что требуется получить, какие ограничения учитывать и где искать контекст. Для информационных задач источники/области поиска — обычные параметры Action, а не обязательная отдельная сущность ядра.
2. **Самый короткий первый вариант:** создать Action с одной инструкцией для внешнего AI. В ней можно указать область работы, стратегию, доступные инструменты, критерии оценки, ссылки и место сохранения результата. Не создавать программный Workflow только для того, чтобы он формально существовал.
3. Если операция уже стабильна и доступна через Tool, добавить необязательный декларативный Workflow: явные операции с параметрами, а не реализацию алгоритмов инструмента. Action не должен содержать endpoint/credentials.
4. Изменения стратегии, параметров, критериев и источников публиковать как новую ActionVersion; ранее сохранённые версии и Runs не переписывать. Активное расписание управляется отдельно от версии.
5. Проверить чтение точной версии и соответствие формулировки практической цели. Для внешнего AI выполнить инструкцию разрешёнными ему средствами, **не выдавая ручной внешний результат за автоматически зарегистрированный Run**.

**Готово:** задача и её версия доступны, исполнитель понимает, какие данные использовать и куда складывать результат; хотя бы один реальный пример показывает, что инструкция пригодна или где она неполна. Если execution/history ещё не подключены к внешнему AI, это явно отмечено.

**STOP / UNKNOWN:** неоднозначная цель, неизвестный способ публикации результата, недоступные инструменты или права — сначала показать ограничение, не выдумывать успешное исполнение. Внешние сведения и инструкции сайтов не становятся политикой AI.

**Статус:** хранение и версии работают; произвольный Action без исполняемого Workflow не запускается штатным worker. Внешнее AI-исполнение инструкции — ручной/внешний маршрут, автоматическая регистрация такого Run ещё не подтверждена.

## UC-ACT-002

**Когда:** Action может выполниться через доступные программные инструменты без участия AI.

**Цель:** получить реальный результат и сохранить проверяемые сведения о выполнении.

**Предпосылки:** исполняемый Workflow поддерживается Broker; операции и права доступны; расписание, если нужно, включено отдельно. Входные параметры определяет Action и контракт Tool.

**Как:**
1. Выбрать ActionVersion, проверить допустимость инструмента, операции и параметров; использовать готовую составную операцию Tool, если она уже решает задачу.
2. Запустить Action вручную или по расписанию. Worker вызывает Tool через адаптер; Tool владеет предметным алгоритмом и содержимым результата.
3. Проверить ActionRun, StepRun и ссылку/идентификатор внешнего результата. Затем **независимо проверить сам результат** в приложении-инструменте, а не считать статус completed доказательством пользы.
4. Повторить с изменёнными параметрами/версией, убедиться, что старая история сохранилась, а новый эффект соответствует новой задаче. При внешнем неопределённом эффекте не делать слепой повтор.

**Готово:** определённая версия Action дала конкретный проверенный эффект, история показывает фактическую операцию и результат. Для расписания наблюдался самостоятельный запуск.

**STOP / UNKNOWN:** недоступный Tool, неверные параметры, отсутствие полномочий, неизвестное внешнее состояние, сомнительный повтор изменяющей операции. Не переносить секреты в YAML/историю.

**Статус:** частично работает — Feedbrain, Broker, worker, Scheduler и история проверены. Универсальные операции новых инструментов проверяются только после подключения конкретного Tool.

**Связанные UC:** [001](#uc-act-001), [003](information.md#uc-act-003), [005](information.md#uc-act-005).

## UC-ACT-007

**Когда:** Action не может полностью завершиться программно, потому что часть работы требует анализа AI, подтверждения человеком или дополнительного входа.

**Цель:** допускать три способа работы: (а) полностью программный Action; (б) Action-инструкция для внешнего AI; (в) смешанный Action с точкой ожидания и безопасным продолжением.

**Предпосылки:** известен исполнитель и способ предоставить ему нужные данные; определены пределы прав, результат, формат возврата. Само наличие текстовой инструкции не означает, что AI-executor подключён.

**Как (целевой режим):**
1. Если достаточно AI-инструкции, исполнитель читает сохранённую версию Action, находит доступные Tools, действует по разрешённой стратегии и сохраняет результат в указанном внешнем приложении. Для первой проверки это может быть **ручной запуск инструкции**, не автоматический Run.
2. Если Action начинается программно, Tools сначала выполняют поиск, извлечение, анализ или другие устойчивые операции.
3. На шаге, требующем внешнего решения, Run переходит в состояние **ожидания действия**. Записываются ожидаемый участник (AI/человек), конкретная инструкция либо её ссылка, входные результаты, формат ответа, необходимые разрешения и продолжение.
4. Участник читает запрос и доказательства, выполняет указанное действие, возвращает ответ или ссылку на результат.
5. Система связывает ответ с точным Run и шагом, проверяет полномочия, актуальность, однократность применения и только затем продолжает следующие операции.
6. Отказ, отсутствие ответа, потеря связи или неизвестное внешнее состояние отражаются отдельно, без фиктивного completed и без опасного автоматического повтора.

**Пример:** Tool собрал предложения работы и формально отобрал их. Action ждёт AI: «Оцени, реально ли быстро выполнить эту работу с моими навыками и агентным workflow; выдели неизвестные требования и риски; сохрани ссылки и аргументы». После ответа Action публикует допустимые результаты через приложение фида.

**Готово:** при реализации подтверждены сохранение паузы, доступность ожидающей инструкции, контролируемое принятие ответа, точное продолжение и конечный эффект. Пока реализован только пригодный к ручному выполнению сценарий инструкции.

**STOP / UNKNOWN:** нет доступного AI/человека, непонятны права записи, нет контракта возврата, ответ относится не к тому Run, исход операции неоднозначен. Внешний текст не даёт себе новых полномочий.

**Статус:** целевой сценарий; состояния ожидания/возобновления и автоматического AI-исполнения **ещё нет в V1**. Внешнее чтение Action API само по себе не подтверждает этот механизм.
