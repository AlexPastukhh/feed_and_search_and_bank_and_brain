# UC-ACT-012 — Зарегистрировать результат работы внешнего AI

**Когда:** пользователь или другой инициатор поручил внешнему AI выполнить
уже сохранённую ActionVersion; работа завершилась, и теперь её нужно
найти в общей истории. Категория Action может быть `research`,
`monitoring`, `general` или иной; **исполнитель и категория независимы**.

**Цель:** иметь достоверный адресуемый факт выполнения с точной версией,
инициатором, идентичностью авторизованного исполнителя, итогом и ссылками
на предметный результат. **Core не запускает AI и не контролирует его
жизненный цикл.** Fortis Repo — возможное средство доступа, не
обязательный исполнитель и не единственная интеграция.

**Предпосылки:** существует разрешённая ActionVersion; внешний AI
уже получил инструкцию и выполнил её доступными ему Tools; известны
фактический исход и проверяемый способ хранения результата. Доступ к
записи истории даётся **конкретному исполнителю и Action** отдельно.
Нет ни требования к Workflow, ни обязательного расписания, ни
автоматически назначенного AI.

**Как:**

1. Прочитать точную ActionVersion и ожидаемый формат результата.
   Инициатор и исполнитель могут различаться, это фиксируется отдельно.
2. Самостоятельно исполнить инструкцию, проверить использованные источники,
   условия доступа и предметные ограничения. Зафиксировать известные даты,
   идентификатор внешнего запуска и его исход; не придумывать отсутствующие
   timestamps. При ошибке регистрировать ошибку, а не успешный отчёт.
3. Если результат сохраняется во внешнем приложении или в Git, получить
   адресуемый ID/URI и **отдельно подтвердить readback**. Указание
   `reported_saved` — заявление исполнителя, а не доказательство Core.
4. После выполнения передать сведения через **разрешённый механизм
   регистрации External AI**. Система связывает их с существующей
   ActionVersion и создаёт общий ActionRun/ActionResult, но не помещает
   запись в Broker queue, не выдумывает StepRun и не пробуждает AI.
5. Повторить **тот же** отчёт с тем же ключом для проверки идемпотентности;
   подмена уже записанного факта должна быть отклонена. Прочитать историю
   по Action и конкретному Run, проверить статус, исполнителя и ссылки.
6. Если это Research — предложения и Evidence рассматриваются отдельно по
   [UC-ACT-009](review-results.md) и [UC-ACT-010](result-lifecycle.md#uc-act-010).
   Если Monitoring — сравнивать только действительно сопоставимые записи
   по [UC-ACT-011](result-lifecycle.md#uc-act-011). Регистрация Run **не**
   утверждает Source/Action и **не** создаёт dataset автоматически.

**Готово:** существует единственный адресуемый внешний Run с точной
версией, отдельной идентичностью исполнителя, известным исходом и
корректно классифицированным состоянием хранения; подтверждено чтение
Run и отдельно — чтение предметного результата. Повтор безопасен.

**STOP / UNKNOWN:** установленный API не поддерживает External AI;
исполнитель не авторизован на запись именно в этот Action; ссылка не
проверена; неизвестен исход/версия; в истории пытаются создать `queued`
через программный endpoint; внешний источник требует секретов в Action;
недоверенная сеть при отсутствии общей защиты остальных API.
Не обходить Fortis Gateway или отсутствие разрешённого credential.

**Статус (проверено 2026-11-11):** контракт и код регистрации добавлены
в `main` через PR №8. На **одноразовой PostgreSQL** прошли 137 тестов,
проверка прежней истории при upgrade/downgrade и запрет `queued`
для External AI. На работающем Windows API маршрут пока **отсутствует**;
`GET /actions/3/runs` и `/actions/4/runs` вернули пустые списки.
Это ещё не end-to-end выполнение на постоянном runtime.
