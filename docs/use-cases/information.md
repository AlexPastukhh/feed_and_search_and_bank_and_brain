# Информационные Actions — повторяемые рабочие сценарии

Эти UC описывают **что можно сделать с системой и как проверить пользу**, а не обязательные этапы новой платформы. Параметры и алгоритмы принадлежат разным уровням по [архитектуре](../ARCHITECTURE.md); что уже проверено — в [PROJECT.md](../PROJECT.md). Названия внешних Tools здесь условные, пока их реальный контракт не подтверждён.

## UC-ACT-003

**Когда:** нужно найти неизвестные варианты, регулярно наблюдать интересующую область или сравнивать изменения — не обязательно просто читать фиксированные RSS-ленты.

**Цель:** позволить Action задать предмет исследования, изменяемую стратегию и входные параметры так, чтобы устойчивую реализацию поисковых и аналитических операций предоставляли Tools.

**Предпосылки:** выбран вопрос/область интереса, описано, как отличить полезный результат; известны фактически доступные источники или поисковые инструменты.

**Как:**
1. Action задаёт цель (например, «найти новые подходы к проблеме», «следить за спросом на определённую работу»), критерии, период и стратегию использования операций. Source — один из обычных параметров Action, особенно значимый для наших информационных задач.
2. Источники могут быть известными сайтами/RSS/API, наборами данных, областью поиска или запросами для обнаружения ранее неизвестных вариантов. Не ограничивать исследование только заранее заданным перечнем URL.
3. Передать параметры Tool. Предсказуемый поиск, дедупликация, вычисление показателей и формальная классификация могут целиком жить внутри Tool; изменяемая последовательность и условия использования разных операций — преимущественно в Action.
4. Инструмент возвращает сведения, ссылки либо сохраняет их у себя; Action направляет результат в выбранное приложение или предоставляет способ его получить.
5. Изменить тему, источники, критерии или стратегию **в новой версии Action**, без переписывания кода Tool, и проверить изменение практической выдачи.

**Примеры:** мониторинг релизов и улучшений AI-инструментов; наблюдение значимых лично пользователю событий и мировых/интернет-показателей; поиск новых способов решения технической задачи; исследование спроса на услуги.

**Готово:** два осмысленно отличающихся запуска дают проверяемые находки с первоисточниками; показано, какую часть поведения определяет Action, а какую — Tool. Для мониторинга результат следующих запусков позволяет отличить новое от прежнего.

**STOP / UNKNOWN:** неизвестна область поиска, доступ запрещён, результаты без ссылок/даты или смысловая оценка выдаётся за формально вычисленную. Не объявлять возможности поискового API, которых он не подтверждал.

**Статус:** целевой поиск/мониторинг; RSS, хранение и FTS Feedbrain работают, но параметризованный широкий поиск через Action ещё не реализован.

**Связанные UC:** [001](actions.md#uc-act-001), [002](actions.md#uc-act-002), [004](#uc-act-004), [005](#uc-act-005). **Владельцы:** [ARCHITECTURE](../ARCHITECTURE.md), [ACTION-CORE](../ACTION-CORE.md); [валидация Workflow](../../src/info_hub/action_workflow.py), [Broker](../../src/info_hub/action_broker.py).

## UC-ACT-004

**Когда:** пользователь хочет найти реальную оплачиваемую работу либо обнаружить косвенные сигналы о новых способах заработка.

**Цель:** получать практические варианты заработка, которые **реалистично освоить и качественно выполнить** с навыками программирования и помощью AI/нескольких агентов, включая незнакомые направления; не ограничиваться текущим стеком.

**Предпосылки:** указаны ключевые навыки, ограничения по времени/риску/бюджету и приемлемый тип работы; доступны инструменты поиска или внешнему AI разрешено провести поиск вручную.

**Как:**
1. Создать Action с заданием: искать .NET и React, **любые заказы на разработку ПО**, программирование на других языках, задачи, где недостающую теорию можно быстро освоить с AI, а также 2D/3D-заказы и другую оплачиваемую работу, где реально построить результативный AI-workflow.
2. Искать как прямой спрос (вакансии, фриланс-заказы, запросы на выполнение работы), так и косвенные сигналы: повторяющиеся потребности, новые инструменты, спрос на трудоёмкие задачи, за которые заказчик готов платить ради экономии времени и доведения результата до качества.
3. Для каждой находки получать ссылку и факты: содержание заказа, требуемые навыки/результат, бюджет и срок, если опубликованы, дату, ограничения, условия площадки.
4. Разделять **опубликованный оплачиваемый заказ**, **непроверенное предложение**, **гипотезу о новом способе заработка** и **идею эксперимента**. Не выдавать прогноз дохода или успешного выполнения за факт.
5. Оценивать применимость: какой результат нужен заказчику, что известно, что придётся изучить, какие подзадачи подходят AI/агентам, что потребуется сделать и проверить самому, какие есть риски качества, лицензий, конфиденциальности и затрат.
6. Сохранять полезные результаты во внешнем приложении фида/списка, с первоисточниками, датой и основаниями оценки. Повторные исследования ищут новое и уточняют старое.
7. **Ближайший путь без новой разработки:** начать с Action, содержащего подробную инструкцию для AI и ожидаемый формат результата; выполнить её вручную с доступными поисковыми инструментами. Затем автоматизировать повторяемое получение данных только там, где это действительно экономит усилия.

**Пример результата:** «Заказ на React UI — ссылка, сумма и срок (если есть), известные требования, пробелы в знаниях, предварительный план работы с агентами, оценка рисков; статус: проверенный заказ / требует проверки». Рядом — гипотеза: «часто встречается запрос на 3D-превью; проверить спрос и качество возможного AI-assisted pipeline».

**Готово:** получена реальная проверенная подборка разнородных задач, пользователь может открыть объявления, понять их пригодность и выбрать варианты для дальнейшего изучения. Результат существует вне текущего чата и доступен повторно, если применён внешний Tool для сохранения.

**STOP / UNKNOWN:** мошеннические/устаревшие объявления, неподтверждённые ставки и требования, правила площадок, недоступные исходники или невозможность обеспечить качество/разрешения. Не выполнять работу, не откликаться и не обещать клиентам результат без отдельного решения пользователя.

**Статус:** целевая практическая задача; инструкция для AI возможна уже сейчас, но автоматический широкий поиск и публикация в выбранный фид ещё не проверены.

**Связанные UC:** [001](actions.md#uc-act-001), [003](#uc-act-003), [005](#uc-act-005). **Владельцы:** [ARCHITECTURE](../ARCHITECTURE.md), [PROJECT](../PROJECT.md).

## UC-ACT-005

**Когда:** пользователь хочет регулярно получать персональную подборку интересной информации и обращаться к ней из AI по запросу.

**Цель:** публиковать результаты Actions в **готовое приложение фида**, а не строить собственный Feed UI или обязательное центральное хранилище в Action Core.

**Предпосылки:** выбран внешний сервис с подтверждёнными операциями **записи/публикации** и **чтения/поиска** для нужного AI/пользователя; проверены формат данных, права, идентификаторы и доступность его интерфейса. Просто наличие OPML-импорта или RSS-читалки этого не гарантирует.

**Как:**
1. Action определяет предмет мониторинга, условия отбора и желаемый результат. Поисковый/аналитический Tool обнаруживает и обрабатывает информацию. Публикацию выполняет инструмент фида либо составная операция уже доступного Tool.
2. Сохранять у публикации первоисточник, дату, ссылку/идентификатор результата и, если поддерживается, связь с Action и результатом его выполнения; полную предметную модель определяет приложение фида.
3. Пользователь просматривает подборки по темам: предложения работы, AI-workflows, изменения технологий/мира, новые способы решения задач.
4. AI получает данные через действительно доступный ему контракт приложения фида или другого источника, отвечает на вопросы «что нового за неделю?» и «какие новые заказы подходят моим навыкам?» **со ссылками на записи и первоисточники**.
5. Проверить повторную публикацию одной находки: использовать возможности дедупликации/обновления выбранного приложения, не разрабатывать новый универсальный data pipeline в ядре.

**Готово:** реальная находка появилась в готовом фиде, читается пользователем и доступна AI через разрешённый Tool; повтор не породил нежелательные дубли. Данные в чужом сервисе не объявляются локальной копией Action Core.

**STOP / UNKNOWN:** приложение не выбрано, нет API публикации/чтения, AI не имеет права доступа, RSS-подписка поддерживается, но персональные записи добавить нельзя. Не утверждать, что OPML импортирован или фид уже создан, без подтверждения.

**Статус:** целевой сценарий; выбор и проверка готового приложения ещё впереди, UI внутри Action System не планируется.

**Связанные UC:** [003](#uc-act-003), [004](#uc-act-004), [006](#uc-act-006). **Владельцы:** [ARCHITECTURE](../ARCHITECTURE.md), [PROJECT](../PROJECT.md), интеграционный контракт будущего выбранного Tool.

## UC-ACT-006

**Когда:** нужно объединить результаты нескольких запусков, исследований или периодов и представить накопленную информацию в полезной форме.

**Цель:** сравнивать изменения, считать показатели и строить таблицы/диаграммы/графики через подходящие готовые Tools, **не создавать универсальный движок представлений в ядре**.

**Предпосылки:** результаты доступны из инструмента-хранилища или внешнего приложения, у них есть даты, источники, достаточно сопоставимые определения показателей и способ чтения через Tool.

**Как:**
1. Action задаёт интересующую тему и период (например, последние 12 месяцев), критерии сравнения, показатели и желаемую форму представления.
2. Инструменты получают ранее накопленные данные и новые измерения, выполняют по контракту расчёты, группировку, сравнение, обновление набора данных.
3. Внешний инструмент представления строит таблицу или график; Action получает адрес результата и сохраняет относящуюся к Run историю.
4. Повторно выполнить Action, затем проверить, что обновилась выбранная выборка или внешний накопительный объект, а не появился ложный «новый» результат из дублей.
5. Открыть график и сверить хотя бы несколько точек с первичными записями, датами, единицами измерения и правилами агрегации.

**Пример:** серия исследований спроса на React/.NET-заказы, затем график количества реально найденных предложений по месяцам; или сравнение нескольких исследований игрового рынка за год. Учитывать, что число найденных объявлений зависит от охвата источников и **не тождественно** объёму всего рынка.

**Готово:** данные нескольких реальных выполнений представлены одним сопоставимым отчётом/таблицей/графиком с проверяемыми источниками и ссылкой на внешний результат.

**STOP / UNKNOWN:** несопоставимые выборки, отсутствующие измерения, неодинаковые определения метрик, неподтверждённые операции записи или неподдерживаемая интеграция. Не выдумывать тренды из недоступных данных.

**Статус:** целевой сценарий, готового универсального слоя сравнения и визуализации в Action Core нет и он не является обязательной целью.

**Связанные UC:** [003](#uc-act-003), [005](#uc-act-005). **Владельцы:** [ARCHITECTURE](../ARCHITECTURE.md), [PROJECT](../PROJECT.md); точный контракт будущего инструмента представлений.

## UC-ACT-008

**Когда:** пользователь хочет улучшить способы достижения целей в своём приложении планирования, используя актуальную внешнюю информацию.

**Цель:** найти новые варианты решения задачи, недостающие критерии, потенциальные ошибки, ограничения и возможности улучшения, не копируя бизнес-логику приложения планирования в Action Core.

**Предпосылки:** существует доступный интерфейс чтения целей, решений, критериев и ограничений планировщика; запись — только при наличии отдельного разрешения и контракта.

**Как:**
1. Action указывает целевую задачу/цель планировщика и инструкцию исследования, параметры и разрешённые Tools.
2. Tool планирования читает актуальный контекст; поисковые/аналитические Tools находят альтернативы, изменения обстоятельств, новые критерии эффективности, возможные ошибки.
3. Результат оформляется как проверяемые **предложения** с основаниями и источниками. Подтверждённые факты, оценки и гипотезы различаются.
4. Сохранить предложения в соответствующем внешнем приложении или адресуемом результате. Изменение действующих решений допускается только по разрешённому сценарию, возможно с ожиданием одобрения пользователя.
5. Повторная проверка учитывает новые сведения и состояние задачи, не переписывает без оснований историю планирования.

**Пример:** цель «увеличить доход», существующие варианты и ограничения в Goal Map; Action обнаруживает новые способы выполнения оплачиваемых задач, предлагает дополнительный критерий затрат времени на обучение и риск низкого качества, сохраняет предложения для просмотра.

**Готово:** конкретная задача планировщика получила новые обоснованные варианты/критерии с первоисточниками и ссылкой, а не просто прошёл вызов API.

**STOP / UNKNOWN:** неизвестный контракт приложения, отсутствие доступа, неподтверждённые права записи, потенциально разрушительное изменение цели. Нельзя утверждать, что Tool Goal Map уже подключён.

**Статус:** целевой сценарий; связанный инструмент приложения планирования пока не подтверждён.

**Связанные UC:** [001](actions.md#uc-act-001), [003](#uc-act-003), [007](actions.md#uc-act-007). **Владельцы:** [ARCHITECTURE](../ARCHITECTURE.md), [SECURITY](../SECURITY.md), [PROJECT](../PROJECT.md).
